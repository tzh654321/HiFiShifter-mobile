```
│   └── remote "upstream" → https://github.com/ARounder-183/HiFiShifter.git

```

`upstream-src` 的 `origin` 已被重命名为 `upstream`，后续在你的 GitHub 账号上建好 fork 后，只需：

```bash
cd upstream-src
git remote add origin git@github.com:<你的账号>/HiFiShifter-mobile.git
git push -u origin develop:develop
```

### ⚠️ 本仓库的两个操作坑（已踩过，务必注意）

1. **`git checkout <分支>` 在本环境会被中断**，中断后工作树会残留大量 ` D`（已删除）文件、并留下 `.git/index.lock`。
   - 恢复方法：`rm -f .git/index.lock && git checkout -- .`（此命令可达，分支切换命令不可达）
   - 规避方法：不要用 `git checkout <branch>` 切分支；需要看别的分支用 `git show <branch>:<path>`，需要导出整棵树用 `git archive`。
2. **恢复 184 MB 模型文件需要时间**，任何涉及全树改写的 git 操作都必须给足超时（实测 `git checkout -- .` 需要 1 分钟以上），否则会被中断并留下半删状态。

**为什么值得同步**（不是例行维护）：这两处新模块正压在我们的移动端工作面上 ——
`penInput.ts`（悬停副作用门控、橡皮端 `button:5`、笔杆键 = 右键语义、**掌压拒识**）1:1 影响
`touchGesture.ts` 的指针分派；`rightDragContextMenuGuard.ts`（window 捕获阶段统一拦截 +
「下一次 pointerdown 无条件解除武装」的闸门）与我们**整条移动端 contextmenu 策略**
（单指绝不 `setPointerCapture`，靠原生 long-press 合成 contextmenu）建立在同一套机制上。

**同步方式**（`git checkout` 在本仓库不可用，见 `docs/09`）：

1. `git fetch upstream develop --no-tags`（只 93 个对象 / 3.5 秒）
2. 把 `git diff HEAD FETCH_HEAD` 拆成两段应用：
   - **我们没碰过的 28 个文件** → `git apply`（全清）
   - **双方都改过的 6 个文件** → `git merge-file` 三方合并（ours = 工作树 / base = 旧 HEAD /
     theirs = 新 HEAD）
     ⚠️ 不能用 `git apply --3way` 一把梭：它对**工作树已改过**的文件报 `does not match index`，
     而 `git apply` 是**全或无**的 —— 一个文件失败，整个补丁都不落盘（实测确实什么都没写）。
3. 移动基线指针用 `git update-ref refs/heads/develop <sha>` + `git reset --mixed`
   （**不写工作树**，只重建 index）。

**结果**：6 个重叠文件里 5 个自动合并，只有 `App.tsx` 在**顶部 import 区**冲突 1 处
（两边都在同一位置加 import）—— 手工保留双方即可。合并后：`tsc -b` 零错误、
`verify-patches.sh` OK 5 / 失败 0（47 个文件逐字节一致）、工作树无意外删除。
