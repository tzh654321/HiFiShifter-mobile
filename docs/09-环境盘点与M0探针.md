## 2. 三个关键发现

### 2.1 ⚠️ 本机的本地代理已失效，会毒化所有构建工具

```
HTTP_PROXY = HTTPS_PROXY = http://127.0.0.1:7892
```

实测（`--range 0-200` 的 GET 请求）：

| 目标 | 走代理 | 直连（`--noproxy '*'`） |
| :--- | :--- | :--- |
| `api.github.com` | **000** | **206** ✅ |
| `dl.google.com`（Android SDK/NDK 源） | **000** | **206** ✅ |
| `index.crates.io` / `static.crates.io` | **000** | **206** ✅ |
| `registry.npmjs.org` | **000** | **206** ✅ |
| `static.rust-lang.org` | **000** | **206** ✅ |
| `github.com` | — | **206** ✅ |

**结论：这台机器直连国际网络是通的，坏的只是本地那个代理进程。**

影响面：`git` / `curl` / `cargo` / `npm` / `gradle` 都会读 `HTTP_PROXY`，不屏蔽就会全线超时。
**这解释了 2026-09-17 那次 `git fetch` 失败**（`Failed to connect to github.com:443 over proxy 127.0.0.1`）——当时我误判成"网络偶发"，实际是代理挂了。

**处置**：`scripts/android-env.sh` / `.ps1` 里统一把代理变量清空并设 `NO_PROXY=*`。
如果你把代理客户端重新开起来（端口仍是 7892），把脚本里那几行注释掉即可恢复。

### 2.2 ⚠️ Android 工具链必须停在 JDK 17

重力四子棋项目的 `android/tools/build.py` 里留了一条**已验证**的注释：

> R8/D8 与 JDK 21 存在兼容 bug（匿名内部类 NPE），标准做法是用 JDK 17 运行
>
> 「JDK 21 的 javac 即使 `--release 8` 生成匿名内部类 class 文件，也会触发 build-tools 34 自带 R8/D8 的 NPE（已验证）。必须整个工具链使用 JDK 17 编译与 dex。」

所以尽管 `java` 在 PATH 上指向 JDK 21，**所有 Android 构建都要显式把 `JAVA_HOME` 指到 `D:\Download\_tools\jdk-17`**。
这条与 Tauri 官方要求一致（Tauri Android 要求 JDK 17），两条独立来源互相印证。

### 2.3 ✅ 重力四子棋项目留下了三样可直接复用的东西

| 可复用物 | 价值 |
| :--- | :--- |
| **JDK 17**（`D:\Download\_tools\jdk-17`） | 省掉一次 JDK 安装；且是**已被验证过能用**的组合 |
| **`android/inject/*.js` 注入层模式** | 该项目已在用「把 JS 注入脚本随 assets 一起打包、由页面加载」的做法（`g4-mobile.js` 23.8 KB）。**这正是 [docs/01 ADR-004](01-移植方案总览.md) 里规划的 `android/inject/` 模式** —— 你的工作习惯和本方案的设计是同一个路子，说明这条适配路径可行性已经被实践过 |
| **签名 / 安装 / 调试的既有姿势** | `g4.keystore`（RSA 2048 / 有效期 10950 天 / alias `g4`）、`install.ps1`（`adb install -r` + `monkey` 启动）、Manifest 里长期保留 `android:debuggable="true"`（正是我们 CDP 调试所需）。照同一套姿势给 HiFiShifter 做一份即可 |

另外那个 Manifest 里有两个值得注意的选择：

- **`configChanges` 显式列了 `orientation|screenSize|screenLayout|smallestScreenSize|keyboardHidden|uiMode|density`** —— 这样旋转/改密度时 Activity **不会重建**。对我们的三套布局（[docs/04 §2](04-小屏排版适配.md)）**很关键**：Activity 一重建，WebView 就重载，编辑状态全丢。Tauri 生成的 Manifest 要**核对**是否覆盖了这些项。
- **`windowSoftInputMode="adjustNothing"`** —— 软键盘不改变窗口尺寸。这与我们计划用 `visualViewport` 自行处理键盘的做法是不同的取向，需要实测后二选一。

## 5. 执行过程中发现的新坑（务必记住）

### 5.1 ❌ Rust 官方源在本机被限速到不可用，必须走镜像

| 源 | 实测速度 |
| :--- | :--- |
| `static.rust-lang.org`（直连） | **7.7 KB/s** —— 一个组件下 16 分钟没下完，`rustup default stable` 卡死 |
| `mirrors.tuna.tsinghua.edu.cn/rustup` | **4.29 MB/s** —— 71 MB 用 16.6 秒；整套工具链 + 2 个 android target 在 1 分钟内装完 |

**已固化**：`scripts/android-env.sh` / `.ps1` 里设了 `RUSTUP_DIST_SERVER`；项目根 `.cargo/config.toml` 里把 crates.io 换成 tuna 稀疏索引（`crates` 下载缓存 543 MB 也是几分钟内下来的）。

> 测量时的一个陷阱：`curl -o /dev/null -w '%{size_download}'` 在这个环境里**恒返回 0**，会让人误判成"下载失败"。
> 必须**写到真实文件再 `stat`**，或用管道看到实际字节。我在这上面绕了弯路。

### 5.2 ⚠️ rustup 的 toolchain 会处于"看似已装、实则残缺"的状态

第一次安装被中断后，`rustup default stable` 的行为是：

```
info: using existing install for stable-x86_64-pc-windows-msvc
info: default toolchain set to stable-x86_64-pc-windows-msvc
  stable-x86_64-pc-windows-msvc unchanged - (error reading rustc version)
```

它**认为已安装**、直接跳过，但目录里缺 `lib/rustlib/manifest-*`，`rustc --version` 能跑（因为 shim 在），一到真正编译就炸：

```
error: linking with `link.exe` failed: exit code 1181
error: only metadata stub found for `rlib` dependency `std_detect`
```

**这两个报错极具误导性**——看起来像 MSVC 链接器缺失或依赖损坏（我一开始就误判成 MSVC 没装，白查了一轮），根因其实只是 **toolchain 目录不完整**。

**修复与教训**：

1. 处理办法：`rustup toolchain uninstall stable` **彻底删掉**再 `rustup default stable`（只 `rustup default` 没用）。
2. 装完必须验证，不能只看 `rustc --version`：
   ```bash
   ls ~/.rustup/toolchains/stable-x86_64-pc-windows-msvc/lib/rustlib/manifest-*
   # 应看到 manifest-cargo / manifest-rustc / manifest-rust-std 三个
   ```
3. ⚠️ **rustup 重建 toolchain 会冲掉已添加的 cross target**。本次 `rustup target add aarch64-linux-android` 装过一次，toolchain 被 auto-install 重建后又没了 —— **每次动过 toolchain 都要重跑 `rustup target list --installed` 确认**。

### 5.3 ✅ MSVC 链接器其实是齐的（别被 Git Bash 骗了）

- VS 2022 Community 已装，MSVC 工具集 **14.41.34120**，真 `link.exe` 在
  `C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Tools\MSVC\14.41.34120\bin\Hostx64\x64\link.exe`
- Windows SDK **10.0.26100.0** 已装；另有 `VS 18 BuildTools`
- ⚠️ 在 Git Bash 里 `which link.exe` 返回的是 **`/usr/bin/link.exe`（coreutils 的硬链接工具，假货）**。
  rustc 走 VS 注册表/vswhere 检测，不受这个影响，但**人工排查时别被它误导**。

最小验证（确认宿主工具链可用，非常值得一跑）：

```bash

# 一个空 main.rs 的 crate
cargo build && ./target/debug/hellotest.exe
# 期望输出：host toolchain ok: x86_64
```

### 5.4 模拟器与虚拟化（⚠️ 含一处重要更正）

| 项 | 结果 |
| :--- | :--- |
| emulator | ✅ 37.1.11.0（本次装） |
| `emulator -accel-check` | ✅ **WHPX 10.0.26100 已安装且可用** |

#### ❌ 更正：x86_64 宿主**跑不了** arm64 镜像（不是慢，是直接拒绝）

```
FATAL | Avd's CPU Architecture 'arm64' is not supported by the QEMU2 emulator on x86_64 host.
        System image must match the host architecture.
```

我最初按 ADR-009 建了 3 个 arm64 AVD 并下了 1.5 GB 的 arm64 系统镜像，**全部不可用**。
（教训：**下大镜像之前应该先用最小代价验证一次能不能启动**。）

WHPX 只能加速 **x86/x86_64** 镜像；Google 已取消 x86 宿主对 arm 镜像的跨架构模拟。

#### ✅ 可行形态：x86_64 镜像 + 本地临时 x86_64 debug 构建

| 项 | 值 |
| :--- | :--- |
| 镜像 | `system-images;android-35;google_apis;x86_64` |
| 启动耗时 | **实测 44 秒**（WHPX 加速） |
| 设备 | `emulator-5554` / API 35 / x86_64 |
| 物理 → CSS | 1080×2400 @ 480dpi → **360 × 800 CSS**（正是设计值） |

已建的 AVD（**x86_64**）：

| AVD | 分辨率 @ 密度 | 等效 CSS | 布局模式 |
| :--- | :--- | :--- | :--- |
| `hs-phone-small` | 720×1280 @ 320dpi | **360×640** | phone |
| `hs-phone-tall` | 1080×2400 @ 480dpi | **360×800** | phone |
| `hs-tablet` | 1600×2560 @ 320dpi | **800×1280** | tablet |

启动：
```bash
D:/Android/Sdk/emulator/emulator.exe -avd hs-phone-tall -no-snapshot-load -no-boot-anim -gpu swiftshader_indirect
```

配合的 Tauri 命令：
```bash
npx tauri android dev   --target x86_64     # 本地调试用（模拟器能装）
npx tauri android build --target aarch64    # 发布用（ADR-009）
```

> **边界**：那份 x86_64 包**只用于本地调试，绝不进发布产物**。
> arm64 的真实行为（音频、性能、ABI、OOM 阈值）仍然只能靠真机——模拟器替代不了。

**可回收**：arm64 系统镜像现在是纯死重量（约 1.5 GB）：

| 项 | 状态 |

编译过程中实际修掉的 5 个问题（都是"编译器一跑就明确"的类型，不影响探针设计）：

| # | 问题 | 修法 |
| :--- | :--- | :--- |
| 1 | `tauri.conf.json` 里 `bundle.targets: ["apk"]` | `apk` 是 mobile-only 目标，在桌面 schema 非法 → 删掉该字段 |
| 2 | Windows 桌面构建缺 `icons/icon.ico` | 生成了 16/32/48/256 四尺寸 ICO |
| 3 | `build_output_stream` 找不到 | 它定义在 `cpal::traits::DeviceTrait`，补 import |
| 4 | `commit()` 报 "expected bool, found Result" | **`EnvironmentBuilder::commit()` 返回 `bool` 而不是 `Result`** |
| 5 | `execution_providers()` 在 `Session` 上不存在 | 删掉；EP 要在 `SessionBuilder::with_execution_providers(...)` 上设 |
| 6 | `commit_from_file` 借不到 `&mut self` | 先 `let mut builder`，不要挂在 `and_then` 闭包里 |

> **有效做法**：API 签名不要猜——直接读本地缓存的 crate 源码：
> `~/.cargo/registry/src/<mirror>/ort-2.0.0-rc.13/`，
> `grep -n "pub fn commit" src/environment.rs` 一眼就能看到真实签名。
