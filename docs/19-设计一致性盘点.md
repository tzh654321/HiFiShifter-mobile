# 19 · 设计一致性盘点（弹窗 / 菜单 / 浮层）

> 需求（用户原话）：
> 「设计统一化：如同类菜单/窗口用相同的打开动画、背景处理、控件样式、字号、描述词
> （确认还是确定，关闭还是完成）（就比如储存设置的窗口位置、背景模糊、层级顺序都有问题，
> **不要只做这一例，多找找类似的**）」
>
> 本文**只做盘点与提案，不改任何代码**。所有结论均带 `文件:行号` 证据。
> 盘点对象：`upstream-src/frontend/src/` 下全部浮层（弹窗 / 菜单 / 浮条），共 **48 个**。
>
> 关联：`docs/17-踩坑速查.md` §E22（统一动效层）、`docs/TASKS.md` §E28（横屏视口 = 屏幕 − 刘海）。

## 2. 「不一致点」清单（按严重度排序）

### 🔴 P0-1　`z-index` 阶梯形同虚设：同类浮层跨 3 个数量级，且与 CSS 约定矛盾

**现象**：`index.css:262-272` 白纸黑字定了阶梯（菜单 999 / 工具栏 600 / 操作记录 500），
但实际取值从 `2` 一直散到 `99999`，**同一族内部都不一致**。

**证据（同类对照）**：

| 对照 | 取到 A | 取到 B | 问题 |
| --- | --- | --- | --- |
| 右键/上下文菜单 | `ClipContextMenu.tsx:452` = `999` | `EditContextMenu.tsx:143` = `9999` | 同类差 10×；且 9999 > 弹窗约定 1000 ⇒ 右键菜单会压住弹窗 |
| 工具栏菜单 | `ActionBar.tsx:602`/`:1171` = `600` | `ActionBar.tsx:1951` = `50` | **同一个组件文件内**两个值（600 vs 50） |
| 轨道/胶合菜单 | `TrackAreaContextMenu.tsx:62` = `999` | `GlueContextMenu.tsx:15` = `50`、`TrackList.tsx:2956` = `50` | 同为右键菜单，50 vs 999 |
| 手机菜单 | `MobileTopBar.tsx:850` = `41` | `MobileBottomBar.tsx:806` = `41`（✅ 一致） | —— 但 41 与桌面类右键菜单 999 不可比 |
| 弹窗 | Radix 弹窗 = `1000`（`index.css:275-277`） | 自绘弹窗 = `60/61`（`StorageSettingsDialog.tsx:108` 等） | 同类差 16× |
| 弹窗（越级） | Radix 弹窗 = `1000` | `KeybindingsDialog.tsx:322` = `9999` | 同一族弹窗差 10×；9999 本是「全屏选择」档（`index.css:264`） |
| 浮动工具窗 | `ClipFormantToolWindow.tsx:230` = `260` | `VibratoAdjustOverlay.tsx:175` = `60` | 两个都漂浮在时间轴上，260 vs 60 |

### 🔴 P0-2　背板三种做法：`0.35 + 模糊` / `0.45 无模糊` / `全透明`

**现象**：弹窗的「背景处理」不统一，用户点名「背景模糊…有问题」。

**证据**：

| 做法 | 证据 |
| --- | --- |
| `var(--qt-overlay)` = `rgba(0,0,0,0.35)` **+ `blur(2px)`** | `index.css:43`、`:255-259`（Radix 弹窗） |
| `rgba(0,0,0,0.45)` **无模糊** | `StorageSettingsDialog.tsx:94`、`ProjectSettingsDialog.tsx:93`、`MetronomeSettingsOverlay.tsx:91` |
| `bg-qt-overlay`（=0.35，**无模糊**） | `MenuBar.tsx:1565`、`:1653` |
| **完全透明**（不遮不糊） | `MobileTopBar.tsx:834`、`MobileBottomBar.tsx:587`/`:823`/`:1435`、`QuickSearchPopup.tsx:390`、`TimelinePanel.tsx:6578`/`:6672`、`VibratoAdjustOverlay.tsx:178` |

**建议统一口径**：弹窗/模态一律 `var(--qt-overlay) + blur(2px)`；纯「点外部关闭」的轻浮层可保留透明，

### 3.3 关闭按钮规范

- **位置**：弹窗一律「右上角 ✕（关闭）+ 右下角主按钮」；面板（`.hs-panel-close`，`index.css:1184`）保持左上角不改。

> 🔑 **用户给的判定规则（2026-10-02 口述，**以这条为准**）**：
> 「**关闭**与**保存**的区别在于：后者**能取消**，前者是在**调完选项后就已经生效**的」。
> ⇒ 落地口径：
> · **即时生效**的设置窗（改一下就落库/落 UI）⇒ 收尾按钮是「**关闭**」（不是「确定」「取消」）；
> · **有草稿、可以反悔**的窗 ⇒ 「**取消**」+「**保存**」（或「应用」）。
> 判据是**看它的输入是不是 `onBlur`/`onChange` 就提交**，而不是看它长得像不像设置窗。
> ⚠️ 特别注意：只有「确定」而没有「取消」的窗，**必然是**即时生效 —— 否则用户无从反悔。
- **主按钮文案**（收敛到 3 个通用 key）：
  - 只读/信息类（存储设置、工程设置、关于、时间线显示）→ `close`（关闭）
  - 需落地一次编辑（吸附网格、音高吸附、分割过渡、EditDialogs）→ `ok`（确定）
  - 有「改完即生效 + 可撤销」语义（静音检测、外观、变速）→ `apply`（应用，建议把
    `silence_apply`/`appearance_apply`/`clip_rate_editor_apply` 三合一为通用 `apply`）
  - 有「未保存需先存」→ `cancel` + `save`（保存），保留 `AutoBackupDialog.tsx:219-222` 的形态但 key 归一
- **禁止**硬编码文案：`ModelManagerDialog.tsx:92/94/160/165` 必须改走 i18n。
- **专用 key 保留但收敛**：`kb_close`/`fb_close`/`benchmark_close`/`undo_history_close`/`mobile_close_*`
  建议全部并入通用 `close`（若担心探针/翻译成本，可保留 key 但值统一为「关闭」）。

### 3.4 文案 key 规范（确认/确定/关闭/完成）

- 通用档只留 5 个 key：`ok`(确定) / `cancel`(取消) / `close`(关闭) / `apply`(应用) / `save`(保存)，
  落在 `i18n/zh-CN.ts:1182-1184` 那一区块（现有 `ok`/`cancel`/`close` 已在此）。
- **「确定 vs 确认」**：`i18n/zh-CN.ts` 只有 `ok:"确定"`；`*_confirm` 系列（如 `quick_export_confirm`=`导出`、
  `tempo_map_clear_confirm`=`清空`）是**动作动词**而非「确定」，命名有歧义 ⇒ 建议改名为
  `quick_export_ok` 一类，或明确「`*_confirm` = 动作按钮文案，不出现『确认』字样」。
- **「关闭 vs 完成」**：全仓**没有**「完成」作为按钮的 key（只有 `status_*_done`=「…完成」，是状态提示，
  如 `i18n/zh-CN.ts:351` / `:366`）⇒ 按钮语义应统一说「关闭」，不要引入「完成」。

- z：`60/61` → `var(--hs-z-modal)` / `−1`。

### 4.4 P1-6 打开/关闭动画：弹窗族补上

- 三个自绘弹窗接 `useExitPresence`（拆掉 `if (!open) return null`，把返回包一层闸门）
  ⇒ **入场 `hs-fade-in` + 出场 `hs-fade-out`**（原来**一个动画都没有**）。
- `MenuBar` 两个全屏模态：`z-[9999] bg-qt-overlay`（无模糊）→ `data-hs-modal-scrim`
  + 卡片 `data-hs-modal-card`（圆角走令牌、有淡入）。
- 弹窗族一律**只动 opacity**：自绘弹窗的背板是它自己的 `position: fixed` 子节点，
  容器有 `transform` 就会变成包含块、背板缩成小方块（与 E22 注释①同坑）。
