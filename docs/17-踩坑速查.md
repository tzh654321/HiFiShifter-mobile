## 视口内核 / 手势层（规范 docs/08，工具 docs/13）

- `renderKernel/scrollKernel.ts` = 视口真值唯一来源；scrollLeft 与 pxPerSec **必须同帧送达**。
- `touchGesture.ts` `TwoFingerGestureController`：死区 16px、单轴锁定 <24px、三指纯平移、
  2→1 指 150ms 冷却；**每表面轴向策略** `attachSurface(el,"x"|"y"|"both")`，会话起手按
  "两指落在哪个表面"定轴（`axisForSession`）；**被禁的轴既不缩放也不平移、也不提交 viewport**。
- ⚠️ **挂表面必须一起决定 `touch-action`**：不滚动的（拍数栏）`none`；**自己滚的**（轨道列）不能禁，
  用 `suppressTwoFingerScroll(el)` 只在 `touches.length>=2` 时 `preventDefault`。
  `pan-y` 不行（双指竖向捏合被当滚动 ⇒ `pointercancel`）。
- **单指绝不 `setPointerCapture`**：捕获态让 WebView 不合成原生 long-press → contextmenu
  （上游 45 处右键菜单全靠它）。第二指落下才 capture。多表面**必须喂同一个 controller**；
  状态机要能**自愈**；拍数栏挂**整行根节点**（tempo-map 标签等是兄弟）。
- 🕳️ 拍数栏 seek：标尺 `onMouseDown` 里 `isLegacyMouseEventFromStylus()` **对 touch 也返回 true**
  ⇒ 手机上没反应。已加 pointer 专用路径 `bindRulerTouchSeek`。
- 🕳️ **值域轴反向**（`valueToY` 里 `y=(1-t)*H`）：行↔值域必须 `scrollTop = -center*rowHeight`。
- 🕳️ 参数编辑器纵向缩放"像没生效"：`syncVerticalScrollbarForViewport` 只写内核镜像、**没回写 ref**，
  而双指 `setVertical` 直接调它 ⇒ 下一手势基准陈旧、缩放被拽回。已回写。
- 🕳️ **纯平移会被 React 丢掉**：缩放入口只写 `horizontalZoomPendingRef`，落地的 `useLayoutEffect`
  依赖里**必须带 `scrollLeft`**（否则 `setPxPerSec(同值)` 被 bail out）。
- 触屏拖拽（滚动条 thumb / range / 旋钮）一律 `touch-action: none`。
- ⚠️ 水平捏合残留 **~3.66px 锚点漂移**（`漂移 = C·(k−1)`，C≈3.9px 是内核 screen↔sec 常数偏移）。
  **已决定不修**（≈0.9ms 不可见），见 `docs/03 §7.7`。

## 实测卡点（全文 docs/10）

1. **`ndk_context` 从未被 Tauri 栈初始化**，cpal 的 Oboe 后端强依赖它 ⇒ 必 panic。解法（零 Kotlin）：
   `JNI_OnLoad` 拿 JavaVM → `ActivityThread.currentApplication()` 取 Context → 全局引用 → 初始化。
2. **onnxruntime**：`.so` 进 `jniLibs/<abi>/`、`load-dynamic` + 裸 soname；**绝不直接引用
   `ort::sys::Ort*`**（⇒ `dlopen` 期 `UnsatisfiedLinkError`），走 `ort::api()`。
3. **路径**：`resource_dir()` = `asset://localhost/`；`app_data_dir()` = `/data/user/0/<pkg>`。
4. **SAF v1**：`pick_file`/`pick_files` 真弹窗；`pick_folder`/`save_file` 返 `None`（v2）。
   `dialog.rs` → `saf.rs`（JNI 回调 + mpsc）→ `HifishifterFs.kt`（**边界物化**到 `cacheDir/saf_import/`）。
   🕳️ 不能用 `env.find_class()` 找 app 的类（native 附加线程只有系统类加载器视野）。
5. **模型导入**：只收 `.onnx`、小文件随包 ⇒ 落点与 `resources.rs` 同树 ⇒ 加载侧一行未改；
   `校验 → .part 原子落位 → 免重启激活` 已实测。
6. **推理 RTF ≈ 0.48** ⇒ 可边播边合成；**块长上限 1024 帧**。
7. **减包（ADR-012）**：**270.8 → 165.1 MB**。🕳️ **改完 conf，APK 一个字节都不会小**
   （tauri 拷资源进 `assets/` 却**从不清理**已删条目；`build-apk.sh §⑤.5` 清期望集外目录）。
   🕳️ 🔴 **`bool::then_some(x)` 会先无条件构造 `x`** ⇒ `AAsset_close(NULL)` → **SIGSEGV**
   （资源随包就**永远测不到**）。🕳️ 减包后必测 **`pm clear` 后全新安装**。
8. **真机喂测试音频**（绕开 SAF）：app 读不了 `/sdcard/` ⇒ **PC 做桥**：`exec-out cat` → PC →
   `push /data/local/tmp` → `run-as cp` 进 `files/media/`；再 CDP 调
   `import_audio_item({audioPath, trackId:null, startSec:null, mediaAudioStreamIndex:null})`。
   ⚠️ `trackId` 传 **`null`** 而非 `undefined`。
9. **参数编辑器两种模式**：**轨道**（音高/共振峰/气声/张力/音量/声像/算法）与
   **音符**（颤音：波长/振幅）。⚠️ `set_param_editor_mode` **不是后端命令**（纯前端状态）⇒ CDP 切不了。
10. **后端片段语义**：全子树选择 ⇒ 粘贴产出 **Tracks fragment**（不是"只多一个块"），
    有单测（`project_fragment.rs`）⇒ 想改属**语义变更，先问用户**。

## CDP 验收（唯一能脚本化验多指的路子，全文 docs/13）

```bash
PID=$(adb -s <serial> shell pidof com.arounder.hifishifter | tr -d '\r')
adb -s <serial> forward --remove-all      # 多设备时必做，否则端口被占
adb -s <serial> forward tcp:9222 localabstract:webview_devtools_remote_$PID
```

- wry 在 **debug 构建**自动开 WebView 调试 ⇒ 零改动。⚠️ 设备须**亮屏 + 应用前台**，
  否则 `visible:false`（`svc power stayon true` + `input keyevent 224`）；🕳️ **真机尤甚**：
  不亮屏量到 `innerWidth=0`。后端日志读 `run-as … cat logs/android.log`（**logcat 抓不到**）。
- 🕳️ **CDP 求值的函数不是闭包**：A 调 B ⇒ B `not defined`。每个函数必须自包含。
- 🕳️ 求值不稳 ⇒ **重建 `forward`** 再试；带 `sleep` 的复杂脚本易超时返回空。
- 🕳️ **DOM `dispatchEvent` 只能验「视觉/布局/属性」，验不了「React 事件是否接上」**：
  `onClick` 比 `onPointer*` 靠后，需完整 pointerdown→pointerup→click 且由真实输入产生
  ⇒ 交互类（点开菜单）**必须 CDP `Input.dispatchTouchEvent` 或真机手测**。
- CDP `Input` 域**没有 `enable`**；双指序列 `touchStart[p1]` → `touchStart[p1,p2]` →
  `touchMove`×n → `touchEnd[]`。坐标是 **CSS px、相对 WebView 视口**。
- 钩子：`__hsViewport()`、`__hsParamViewport()`、`__hsGestureActive`、`__hsOverlaysVisible`、
  **`__hsGestureDebug`**。🕳️ 其中 `rowH` 走 `viewport.get()`，参数面板那条经值域 ref、
  陈旧时**撒谎** ⇒ 用 `ky × rowH0` 反算。
- **直接调任意命令**：`window.__TAURI_INTERNALS__.invoke('<cmd>', {arg})`。第二参数是**对象**、
  键名 `camelCase`（传错报 `missing required key xxx`，正好反查键名）；返回 Promise
  ⇒ 「写 `window.__r=…` + 隔几秒回读」。
- **导航 SAF 选择器**：抽屉(`tap 88 208`) → 目录 → 点**文件卡片中心**。🕳️ 抽屉条目顺序随 MIME 过滤变化。
- 🕳️ **长按菜单要靠真实 `contextmenu`**：CDP `dispatchTouchEvent` 不经过那层识别
  ⇒ `tap --hold` 永远打不开。用 `scripts/_probe-trackctx.mjs`。
- 🕳️ **模拟器的系统剪贴板是空操作** ⇒ 剪贴板类功能只能上真机验。

### 探针方法论（2026-09-27 新批次踩出）

1. **两种触摸驱动不能混用**：React `onPointer*` 用**合成 `PointerEvent`** 最稳
   （CDP 触摸落点/时序不稳：长按菜单打不开、捏合 `kx` 读到上一次会话残留）；
   `TrackList` 的**原生 touch** 监听（排序/左划收起）必须用**真实 `TouchEvent`**。
2. 判"是否可见"用 **`innerText`**（`textContent` 含 `display:none` 的内容）。
3. 点空白避开容器最底 ~**14px**（横向滚动条预留带，点它会滚到末尾）；
   长按/角标类监听挂**内层 span**（事件只冒泡不下降）。
4. 拖拽别靠近容器边缘 **32px**（`DRAG_EDGE_SCROLL_BAND_PX` 会自动滚屏、放大位移）。
5. 探针**互相独立**（开头先"停止播放"）。
6. 块的行坐标取 `[data-hs-track-row]`，别按"扁平下标 × rowHeight"算。

## 🎯 C 盘动不动就满：总根因是 `C:\pagefile.sys`（2026-09-27 查实）

**症状族**（看起来互不相关，其实同一个根因）：

| 表现 | 真因 |
| :--- | :--- |
| Gradle 失败，任务名却跟磁盘无关，日志一句 **GBK 乱码** `´ÅÅÌ¿Õ¼ä²»×ã¡£` | 磁盘满 |
| `build-apk.sh` 一启动就死：**`cygheap read copy failed … Win32 error 299`**，`dirname` 崩溃 ⇒ `$ROOT` 空 ⇒ `//scripts/android-env.sh: No such file` | **MSYS 满盘下的 fork 故障**，脚本没坏 |
| `cargo metadata` → **`os error 193`（%1 不是有效的 Win32 应用程序）** | `~/.cargo/bin/rustup.exe` 被**截成 0 字节**（而 `cargo.exe`/`rustc.exe`/`rustdoc.exe` **全是指向它的符号链接** ⇒ 一个坏、全线坏） |
| `git --version` **输出 0 字节、退出码 0**，所有依赖 git 的脚本报"全都错" | PortableGit 被截成 0 字节 |

**机制**：内存压力（**模拟器在跑** + Gradle / tsc / cargo 并发）会让**系统托管的页面文件**在 C 盘疯涨。
实测：`pagefile.sys` **42.6 GB**；`adb emu kill` 后 **20 秒内 27.6 GB，C 盘 204 M → 16 G**。
把模拟器开回来做探针后又涨回 **28.2 GB、C 盘只剩 1.1 G** —— **这条极顽固**。

### 行动规则

1. **铁律：构建 / 任何重活之前先关模拟器。** 构建根本不需要它，只有**装机 / 探针**才要。
2. **判据**：`df /c` 掉的量**远大于**你正在做的事 ⇒ 直接 `ls -la /c/pagefile.sys`，别去翻别的地方。
   实测"用户目录里没有大头"：最近 75 分钟的大文件合计才 0.41 GB（还都是 Edge 缓存 / 游戏 dump）。
3. **根治（需用户 / 管理员）**：把页面文件挪到 D 盘并**设固定大小**；`powercfg -h off` 再省 `hiberfil.sys`（本机 6.7 GB）。
4. 腾空间只用 `truncate`，**但回收站不释放空间**：`Remove-Item` 与 **`robocopy /MOVE` 都进回收站**

## 双指手势的跨层真相（E 组，2026-09-28 查实）

写在最前：**跨表面的双指手势不要试图"借内核的拖拽手势"**，走**面板既有通道**。
两条硬事实（都已实测，是 A3「双指长按并划动 = slip」原先完全不生效的根因）：

1. **第二指落下时，内核那份手势已经被收掉了。**
   `TwoFingerGestureController.onPointerDown`（`touchGesture.ts`）在 1→2 指过渡里对
   第一指调 `abortPointer(id)` —— 它往 **window** 上派发 `pointercancel` + `pointerup`
   （docs/08 §4.1 的设计，用来中止单指拖拽）；而**内核的收尾监听恰好挂在 window 上**
   （`window.addEventListener("pointerup"/"pointercancel", onGesturePointerUp/Cancel)`）
   ⇒ 内核手势被打回 idle。等 500ms 长按到点、手指开始动时，**内核已没有任何活动手势**。
   - 反证：页面内**合成** `altKey:true` 的单指拖拽（绕开手势层与原生触摸）**能** slip
     ⇒ 内核的 slip 通道本身是好的，缺的只是"起手时机"。
2. **内核的 move 分派不按 `pointerId` 过滤。** 全局只有一份 `gesture`，
   `window.addEventListener("pointermove", onGesturePointerMove)` 消费**所有**指针的 move
   ⇒ 两指各自移动会**轮流驱动同一份位移**，读值在两指位置之间跳，**跳幅恒等于两指间距**
   （实测 36px ≈ 0.37s，肉眼可见）。

⇒ 结论：这类手势的位移应由手势层自己算（**取两指中点**，与捏合缩放同一锚点），
再经**事件桥**交给面板既有的那条通道（本项目用 `hifi:slipPreview` / `hifi:slipCommit`
→ `handleKernelDragPreview` / `handleKernelDragCommit`，几何/吸附/编组/undo/落库整份复用）。

> 顺带：`touchModifiers`（虚拟 Alt/Ctrl/Shift/⌘ 覆盖位）已挂 `window.__hsTouchModifiers`
> （**按引用**，读到的永远是当前值）。触屏上 `PointerEvent` 的这四个字段恒为 `false`
> ⇒ 不挂这个钩子就**分不清"压根没点亮"还是"点亮了又被清掉"**——那是两种完全不同的修法。

### 探针点位三坑（A3 实测，`_probe-slip-twofinger.mjs` 注释里也有一份）

1. **直接导入的块无处可 slip**：块源窗口 = 整段素材 ⇒ 内容顶到媒体边界，
   `slipBoundaryAlignedSides` 的边界吸附会把它按回去 ⇒ 读数"没变化" = **假阴性**。
   必须先 `selectAll + split`（编辑通道 `hifi:timelineEditOp`）造出**源窗口小于素材**的半块。
2. **`hifi:zoomTimelineFocus` 锚定播放头**（`anchorScreenX = 0`）⇒ **先 seek 再缩放**会让
   `scrollLeft = playheadSec × pxPerSec`，块被推到内核容器**左外侧**（实测块左缘 x=72，
   而时间线区从 x=132 才开始 ⇒ 手指落在**轨道头列**的按钮上，什么都不发生）。
   正确顺序：**先缩放（播放头还在 0）→ 再 seek → 再 split**。
3. **触摸下「未选中块的划动 = 平移视野」**（规格 `docs/15` C 列按选中状态分流）
   ⇒ 手势前**必须单击选中目标块**，否则单指拖动只会平移视野。
   ⚠️ 另外：内核容器**底部约 120px 有遮挡带**（贴近底部 40px 的位置横拖拖不动）——
   平移视野要用"容器底上方 ~120px"的空白区。
4. **长按排序类的起手点必须避开"轨道头按钮带"**（E22-⑤ 实测）：行内 `left+40` 一带是轨道头 32×32 的
   圆形按钮（M/S/C / 名称），而 `onStart` 有"**落在交互控件上不参与排序**"的守卫
   ⇒ 拖拽**永不武装**，读数看起来像"排序不动"（不是排序坏了）。
   定性办法：`document.elementFromPoint(x, y)` 应当是**普通 DIV**；轨道头行的已验证空档是 **`left+62`**。

## 🔴 构建链的三个地雷：target 目录跨主体、两个 cargo 抢锁、0 字节 crate（2026-10-01）

### ① 陈旧产物**是另一个安全主体**建的 ⇒ 覆盖/hash 去重都救不了

症状（`cc-rs` 的 build script 报的，看不出跟权限有关）：

```

         to output file '…\X.o': 'Permission denied'
```

判别（一条命令定性）：


⇒ `rm` / `mv` / `cp -f` / `takeown` / `setowner` **全被拒**，只有**目录**能改名（`mv dir dir.stale`）。
🕳️ 撞点集中在**不做 hash 去重**的路径：`build/<crate>-<hash>/out/**`（`build/` 整层可以改走）

所以"前 300 个 crate 编得好好的、突然卡在一个 `.o`"这种**看似随机**的失败就是这么来的。

**解法：换 target 目录**（`CARGO_TARGET_DIR=D:/hfshifter-target-<user>`）。若以产物**所有者**身份运行则不受此限。
🕳️ 别把"改 target 目录"当成万能药 —— 它会连带**全量重编**（见下②的 hash 说明），一次 ~40 min。

## 🔴 出场动画：presence 闸门 + 三个"一动就坏"的坑（E22 第三刀，2026-10-01）

**入场**是纯 CSS（挂载即跑关键帧）；**出场**做不到 —— React 一卸载节点就没有"动画期间"了。
本项目口径：`hooks/useExitPresence.tsx` 挂**闸门**（`open` 变 false 时保留**关门前的子树快照**
一个出场时长、期间打 `data-hs-leaving`），CSS 用 `[data-hs-leaving]` 跑 `hs-menu-out` / `hs-fade-out`。
时长两边手工对齐：`OUT_MS`（ts）↔ `--hs-anim-dur-out-*`（css）。开关仍是 `body[data-hs-no-anim]`
与 `prefers-reduced-motion`（**立即卸载**，与改造前逐字节一致 —— 也是探针的对照组）。

### ① 🔴 闸门里**不要加 DOM 包装层**

第一版为了"让后代选择器兜住组件子节点"，给子树套了一层
`div[data-hs-leaving-root]{display: contents}`。看着无害（不产生盒子），实际**打坏了分屏拖动**：

```
App 的 paintRatio() 按 container.children[0]/[1] **直接改 flexGrow**（避免每帧整树重绘）
⇒ 多出来那层没有盒子 ⇒ flexGrow 写到包装层上 ⇒ 拖动不再改变布局
真机读数：_probe-mobile-split.mjs 2/5、子元素 h=0、边界=-0.0753
```

⇒ 定稿口径：**普通元素**用 `cloneElement` 把 `data-hs-leaving` 打到节点上；
**组件**（`ClipContextMenu` / `FadeContextMenu` / `VerticalDualPanel` / `ClipRateEditor*`）
把注入的同名 prop **转交到自己的根节点**。新增"根是 `role="menu"` 的组件"时**必须记得转交**，
否则出场动画**静默失效**（不报错）。portal 子节点要**拆开再标记**（`$$typeof === react.portal`
者 `React.isValidElement()` 判 false）。

### ② 布局必须**跟着一起滞后**，否则"白淡了"

关掉上方块那一瞬间：下方块 `flexGrow` 从 `1-ratio` 跳到 `1`；且 App 自带那段"单面板归位"
（E10-① 的修复）会**直接写 DOM**、把**正在淡出的那块**也写成 `flexGrow: 1`
⇒ 真机实测淡出中的面板 **419px → 299px**（被压成 50/50），内容还按新高度重排一次。
修法：`useExitLayoutLag(flag)` 让**布局用的标志**滞后一个出场时长；归位循环跳过带
`data-hs-leaving` 的节点。判据 `E22-X4`（关闭前后高度差 ≤6px）。

### ③ 三条探针读数纪律（都误报过一次）

- `hs-mobile-close-panel` 进的是 **`toggleMobilePanel`（翻转，不是关闭）** ⇒ 对**已关闭**的
  面板派发反而会把它**打开**。要"先判在场（且不带 `data-hs-leaving`）再派发"。
- **不是所有面板的 ✕ 都带 `.hs-panel-close`**：那是 `App.tsx` 给 timeline / params 渲染的；
  files / notes 的 ✕ 在各自组件里（Radix `IconButton`）⇒ 点按钮**关不掉**它们
  （会让探针停在"两块平分"状态，把 46.7% 误报成"被压扁"）。
- **中间帧 `opacity` 可能整段采不到**（主线程被面板重排堵住 ⇒ rAF 掉帧，实测某轮只有 23fps）：
  断言"是不是渐变"要同时看动画自身的 `getComputedTiming().progress`，别只信采样到的 opacity。

### ④ 同类：**拖动收尾**的平滑（"过渡只在收尾窗口里开"）

拖动期间代码往往**每帧直接写 DOM**（本项目分屏边界 `paintRatio()` 写 `flexGrow`，为的是不每帧重渲整树），
而抬手才落位（还会 `clamp`、还可能跨阈值关面板）⇒ 修前是**瞬跳**。
做法：抬手时给容器挂一个属性（`data-hs-split-settling`），CSS **只在这段窗口里**上过渡：

```css
[data-hs-mobile-split][data-hs-split-settling] > * { transition: flex-grow 180ms var(--hs-anim-ease); }
```

🔴 **拖动中绝不能带过渡**（否则每帧写一次都会重启过渡 = 橡皮筋、跟手度崩）⇒ 在 `pointerdown` 里
**立即摘掉**属性并清计时器；窗口时长 = 出场布局滞后 + 过渡（本项目 160+180=340ms）。
`flex-grow` 是数值属性、可以插值 ⇒ 布局真的会逐帧过渡（判据：采样到中间高度）。

## 🔑 提权：跨主体产物怎么拿回来（Windows 11 24H2，2026-10-01 实测跑通）

**背景**：本机会话身份是 `hzt`，而工作树 / target 里的产物多由 `tzh` 建 ⇒ 那些文件
`icacls` 读 ACL 都"拒绝访问"，`rm`/`mv`/`cp -f`/`takeown`/`setowner` **全被拒**。
`hzt` 虽在 `Administrators` 组里，但**进程没提权**（`net session` 失败 ⇒ 令牌是 medium integrity）。

**先探测，别猜**（三条）：

```bash
# 1) 系统版本（24H2 才有内置 sudo）→ 本机 26100
powershell -c "(Get-CimInstance Win32_OperatingSystem).BuildNumber"
# 2) UAC 是否还弹窗 → 本机 = 0（"不提示，直接提升"）
powershell -c "(Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System').ConsentPromptBehaviorAdmin"
# 3) sudo 模式 → 本机 = "强制新建窗口模式"
sudo config
```

### ✅ 配方（实测有效）

```bash
sudo C:/Windows/System32/takeown.exe /f 'D:\path\to\thing' /r /d y
sudo C:/Windows/System32/icacls.exe 'D:\path\to\thing' /grant 'hzt:(OI)(CI)F' /T /C /Q
# 复核必须回到普通身份看：
C:/Windows/System32/icacls.exe 'D:\path\to\thing' | head -2      # 应出现 hzt:(F)
```

🕳️ **`sudo` 处于"强制新建窗口"模式** ⇒ 它**另开一个窗口**执行，这边**看不到输出**
（`sudo whoami > f.txt` 得到**空文件**，但命令确实以提升身份跑了）⇒ 成败**只能回普通身份复核**。
🕳️ 本工具链**不允许**从会话里 `Start-Process -Verb RunAs`（安全校验拦"拉起子 shell/LOLBin"），
也不允许从 bash 调 `cmd.exe`/`powershell.exe` ⇒ **能用的只有 `sudo` + 直接调系统工具**。
🕳️ 递归 `takeown /r` + `icacls /T` 对 7.6GB 的 target 也只要几十秒 ⇒ 做完后历史"不可读"文件
全部变成 `hzt:(I)(F)`（含当初让 `oboe-sys` 报 `unable to rename … Permission denied` 的那些 `.o`）。

### 🎯 减包第二处坑：`merged_jni_libs`（AGP 增量目录）

清了 `jniLibs/x86_64/`（那是个 **symlink** → 旧 target 里的 `.so`）之后，APK **仍然是 377MB** ——
那 76.7MB 是**从 gradle 中间产物 merge 回来**的：

```
jniLibs(源) → mergeJniLibFolders → **merged_jni_libs** → mergeNativeLibs → merged_native_libs → strip → 打包
                                   ↑ 增量目录：源里已经删掉的 ABI，它会**原样留着**
```

`build-apk.sh` ⑥.5 原来只清 `merged_native_libs*` / `stripped_native_libs*` ⇒ **补上
`merged_jni_libs*`** 后重建，APK 才真的从 377MB 回到 **300MB**。
判据：`python -c "import zipfile;print([n for n in zipfile.ZipFile(apk).namelist() if n.startswith('lib/')])"`
**只应出现 `lib/arm64-v8a/*`**。

## 触摸类探针的读数纪律（E18 轮，2026-09-30）

> 写任何"双指 / 长按 / 拖动"验收探针之前先读这一节 —— 这五条每一条都曾让**功能明明正常**的用例报红。

1. **CDP `Input.dispatchTouchEvent` 与 `Runtime.evaluate` 是两个通道** ⇒ 紧跟输入之后的求值常拿到
   **上一帧**的值（曾把"已点亮的修饰键"读成没点亮、把已生效的拖动读成没动）。
   对策：每次读**两遍**，中间隔 140ms，取第二遍。
2. **一次 `touchMove` 会拆成两个 `pointermove`**（每指一个）。所以"越过 16px 死区"的那一跳要
   **一次给足 16px**：中间帧只有 8px、`armed` 不亮，基线才是确定的（`span₀ = 起始 + 16`）。
   若按小步推进再"读 armed"，会读到中间帧的基线，期望值就差几 px。
3. **竖直缩放只能在"全屏参数面板"上测**：分屏时参数画布只有 ~89px 高，做 60~80px 的竖直分离度时
   手指贴到画布边缘，被上/下浮层吃掉 ⇒ 只有一指进控制器 ⇒ 整个手势"没反应"（看着像解算坏了）。
   切全屏：`hs-mobile-switch-tab{tab:'params'}` → `hs-mobile-close-panel{key:'timeline'}`，画布 ~500px。
4. **`pitch` 的 `span=6` 已是值域下限** ⇒ zoom in 会被 `clampViewport` 吃掉（表现为"缩放没生效"）。
   测竖直缩放一律用 **zoom out**（两指靠拢）。
5. **参数面板的横向可滚范围与轨道视图共享**（`resolveTimelineScrollRange`，按工程长度 + 视口宽算）：
   工程短时余量只有几十 px，平移两个方向都会"立刻钉住" ≠ 手势坏了。
   要测平移 / 惯性请换**时间线面板**，并先用双指横向张开把 pxPerSec 放大出余量。
6. 🔴 **下触摸前必须先开触摸仿真**：不先 `Emulation.setTouchEmulationEnabled {enabled:true,maxTouchPoints:5}`
   就 `Input.dispatchTouchEvent`，会**卡死到 30s 超时**（2026-10-01 实测，白查了一轮）。
   坐标还要 `Math.round`，并带上 `radiusX/radiusY/force` —— 与 `_probe-mobile-split.mjs` 对齐。
   （对照：`Runtime.evaluate` 那条通道一直是好的，所以"能读到 DOM 但一碰就超时"= 这条。）
7. 🔴 **判"有没有 CSS 过渡"要看 `transitionDuration`，不是 `transitionProperty`**：
   后者的 CSS 初始值就是 `all`、而时长默认 `0s` ⇒ 只看属性名会把"没有过渡"读成"有过渡"
   （E22 第四刀第一版探针就这么误报了两条）。取**实际时长**判定。

## WebGL context 只有 8 个，且丢失后不会自己好（E10-②，2026-09-30 实测）

> 触发场景：**拖上工具栏反复切换「参数全屏 ⇄ 参数+轨道分屏」10 次内触发参数界面白屏**。

### 硬事实（模拟器 SwiftShader 实测，`scripts/_dbg-ctx-lifecycle.mjs`）

| 问题 | 读数 |
| :--- | :--- |
| `getContext("webgl2")` 超限会返回 null 吗？ | **不会**。连开 60 个，`nullAt = -1` —— 浏览器**静默强制丢失最旧的**。⇒ 靠返回值判"创建失败"是错的 |
| 同时能活几个？ | **8 个**（不是常说的 16）。**分屏（参数+轨道）稳态实际占 5 个**（时间线 2 + 参数 3：波形 / 网格 scene / 键盘轴 axis）。⚠️ 别信"稳态 7 个""分屏 9 个"的旧读数 —— 那是**探针自己造出来的**（见下"测量即污染"） |
| 反复切换会累积吗？ | **不会**（2026-10-01 实测，`_dbg-gl-inventory.mjs`）：页面加载前注入包装、`Page.reload` 后从零计数，12 轮「拖手柄切全屏/分屏」后 `live` 恒 **5**、孤儿 **0**，36 个中途新建的 context 全部 `lost=1` 且已移出 DOM ⇒ `dispose()` 的释放是真的 |
| `WEBGL_lose_context` 能用吗？ | 活着的 context 上 **100% 可用**；`loseContext()` **立刻生效**（释放后 8 个全变 lost） |

### 两层真因（症状不同！）

1. **整页空白**：`Canvas2dWaveformRenderer.paint()` 拿不到 2D 上下文时 `throw`，而它跑在**帧回调**里
   ⇒ 未捕获异常 ⇒ **工程当时没有任何 ErrorBoundary** ⇒ React 18 卸载整棵树 ⇒ `#root` 子节点 0。
   取证：`logs/android.log` 全轮只留一条 `Uncaught Error: Canvas 2D is unavailable at D.paint ← at Object.current`。
2. **单块画布永久白屏**：context 被强制丢失后，**钢琴窗/时间线内核从不处理 `webglcontextrestored`**
   （program 已失效、无人重建）⇒ 那个面板再也画不出东西。

### 修法

- 渲染路径**绝不抛错**（这一帧不画 + 只提示一次）；新增应用级 `AppErrorBoundary`（放在 I18n/Theme 之内，
  出错子树换成可读报错界面 + 重新加载，异常照旧回传后端日志）。
- `glContext.ts` 在 `webglcontextrestored` 时广播 `hs-gl-restored`；`App.tsx` 监听 → bump epoch → 面板块换 `key`
  ⇒ 内核重建（走既有路径；带 **1.6s 冷却 + 上限 6 次**防抖动）。
- `dispose()` 必须**真的调** `glHandle?.dispose()`（钢琴窗原先只 `= null`，每次挂载漏 3 个）；
  探测用临时 canvas 探完即 `loseContext()`。
- **降每面板的 context 数**（2026-10-01）：overlay（播放头/选区）原先**独占一块 GL 画布**，
  改为**复用主 GL 画布**（"曲线还在 Canvas2D"这个原设计前提在阶段 3 之后已失效；四层本来就在
  同一个 `draw()` 里按序画）⇒ 参数面板 GL **4 → 3**，分屏稳态 6 → 5。
  ⚠️ 共画布后 `drawGlOverlay()` **绝不能再 `clear()`**，否则会抹掉同帧的网格/曲线。

### 🔴 探针纪律：**测量 `getContext` 本身会创建 context**

健康检查里写 `canvas.getContext("webgl2")`，会在**尚无任何 context 的画布上造一个** ——
既吃那 8 个名额，又把本该 2D 的候补画布变成 GL 画布。实测它把"分屏 4 个 GL"**报成 9 个**，
还自己贡献了每轮 2 条 `Too many active WebGL contexts`（改成非侵入式后 **×20 → ×0**）。

⇒ **只在包装器里记一次（WeakMap），健康读数只读已记录的 context 对象调 `isContextLost()`**（只读不创建）。

> 更彻底的姿势（`scripts/_dbg-gl-inventory.mjs`）：用 CDP `Page.addScriptToEvaluateOnNewDocument`
> 在**页面加载前**注入包装，再 `Page.reload` —— 连 app 启动期建的 context 也能从零记全，
> 还能报出"哪些已不在 DOM"（孤儿）。只靠"页面跑起来之后才注入"会漏掉早期创建的那批。

### 相关：帧回调抛错的代价 & 全量快照覆写 UI 态

- **帧回调里 `throw` = 整个 App 消失**（没有 ErrorBoundary 时）。凡是渲染/帧路径，宁可"这一帧不画"。
- `applyTimelineState` 会**无条件**采纳快照的 `selected_track_id/selected_clip_id`
  （`applyTimelineTracksOnly` 也会覆写 `selectedTrackId`）⇒ 凡"不改变选中语义"的命令（如辈分调整）
  必须传 `{ preserveSelection: true }`，否则选中会在异步 fulfilled 里**凭空跳走**（E7）。
  ⚠️ 加护栏时要**两级都加**，只改下游那处会被上游的先调用覆盖掉。
- **"有概率 / 未能复现"的竞态，优先用 reducer 单测钉死**：把"前端选中 B、快照说 A"的分歧态直接喂 reducer，
  断言结果仍是 B；再拿一个**未加护栏**的命令作对照组证明机制真实存在（否则判据可能空转）。

## CDP 探针的两条硬纪律（2026-10-01 各踩一次）

### ① `Page.reload` 之后，`Runtime.evaluate` 会**落在旧 execution context**、读什么都返回空

症状极像"页面坏了"：`document.querySelectorAll('[data-hs-pane]')` 返回 `[]`、`panes: []`，
**而同一时刻 `adb exec-out screencap` 截图里面板/控件全都在**。

⇒ reload 会换掉 execution context，而旧连接仍指向老的。**要么 reload 后重新 `Cdp.attach`**，
要么干脆别 reload（例如"改 `localStorage` 让设置生效"这种需求，宁可接受旧值，
也别让整轮探针读到假空）。
**判据**：只要"截图有、求值为空"，先怀疑这条。

### ② 探针选择器必须跟**设备上那个包的版本**对齐

真机当时装的是 09-30 **15:50** 的包，而 `data-hs-pane`（面板容器属性）是 **E22（20:xx）**才加的
⇒ 探针拿它当"面板是否存在"的判据，**全线误判成"面板都不见了"**，白查一轮。

⇒ 换设备 / 换包之前，**先确认包里有没有你要的钩子**（例如 `eval` 一句
`document.querySelector('[data-hs-pane]')`，或 `grep` 一下该属性是哪个提交引入的）。
`data-hs-mobile-split` 比 `data-hs-pane` 老，找不到后者时可先用前者兜底。

### ③ 不是所有按钮都能用 CDP **触摸 tap** 驱动 —— 有些只能 `el.click()`

实测（2026-10-01）：`MobileTopBar` 的 6 个菜单按钮、手机参数工具行的 👁 按钮，
用 `Input.dispatchTouchEvent`（tap 70ms）**点了完全没反应** ——
`elementFromPoint` 命中正确、`getComputedStyle().display` = `flex`、按钮就在可视区，
但 `aria-expanded` / 面板状态**一律不变**；同一元素换 `el.click()` **立刻生效**。

⇒ 纪律：**只验"文案/状态"的探针可以直接 `el.click()`**（别为了"像真手"卡死在 tap 上）；
**验手势的探针才必须用真实触摸序列**，而且要先跑一遍"tap 是否有效"的前置自检。
（同源的邻居坑：`Page.reload` 会让 CDP 的 execution context 失效，见本文上一条。）

### ④ 参数曲线类探针：**先点亮"当前编辑轨道"**，再拖

参数面板编辑的是钢琴窗的 `rootTrackId` = `resolveRootTrackId(tracks, selectedTrackId ?? tracks[0])`
—— **没有任何轨道被选中时会回退到 `tracks[0]`**（通常是没有音频的 `Main`）。
而空轨上 `set_param_frames` **回 `ok:true`，`get_param_frames().edit` 却恒为 `[]`**（写进去不存）
⇒ 拖动"提交成功"、探针读数永远 Δ0，看起来像"产品的拖动坏了"。

⇒ 纪律：这类探针必须先 `tap` 一下**块所在轨道的轨道头**（`[data-hs-track-row="<id>"]` 左上内缩 30,20），
并**断言基线可读**（`edit.length > 0`）再往下走；读数用**逐帧差分 `Σ|aᵢ−bᵢ|`**，
**别用"非零帧个数"**（绘制模式是**覆写**曲线、个数不变 ⇒ 对该模式恒 Δ0）。

### ⑤ 别想在页面里给 `invoke` 打桩

`__TAURI__.core.invoke` 与 `__TAURI_INTERNALS__.invoke` 都是 **`writable:false`** 的普通数据属性
（无 getter、不可配置）⇒ `obj.invoke = fn` 在非严格模式下**静默失败**：赋值不报错、
`typeof obj.invoke` 仍是 `"function"`，看起来"挂上了"，其实日志永远是 0 条 → 会误判成"前端没提交"。
⇒ 要证明"提交到后端了"，**直接读后端**（如 `get_param_frames`）——这也是更硬的证据。

## ⛔ 构建类：三个"报错指向完全别处"的坑（2026-10-02，为此白查一整轮）

### ① 构建前**必须**清掉 gradle 守护进程 —— 否则 cargo 会报 `拒绝访问 (os error 5)`

症状（`tauri android build` 收尾）：

```
error: failed to link or copy `…\debug\deps\libbackend_lib.so` to `…\debug\libbackend_lib.so`
Caused by: 拒绝访问。 (os error 5)
```

**真因**：`tauri android build` 的 Rust 编译是 **gradle task `rustBuild<Abi>Debug`** 里跑的
⇒ **cargo 是 gradle 守护进程的子进程**。守护进程是**长期存活**的，它一旦带着"坏令牌 /
残留句柄"，子进程的文件操作就被拒；而**同一个操作在守护进程之外手工执行完全正常**
（实测：Python `os.remove` + `os.link` + 读回 `ELF` 全通，同目录新建同名文件也通）
⇒ 从错误信息完全推不到真凶。日志里的铁证是这一行：

```
Execution failed for task ':app:rustBuildX86_64Debug'
```

**修法（已固化进 `build-apk.sh` §④.4，见 `HS-DAEMON-HYGIENE`）**：

1. `./gradlew.bat --stop` —— ⚠️ **必须带 Windows 形式的 `GRADLE_USER_HOME`**（`D://gradle-home`）。
   本项目用的是 D: 那份；不带就只停了 `~/.gradle` 里那份，**白停**
   （原来的 `--stop` 就写在 `GRADLE_USER_HOME` 赋值**之前**，所以从来没停过对的那份）。
2. `export GRADLE_OPTS="$GRADLE_OPTS -Dorg.gradle.daemon=false"` —— 不复用任何既有 daemon，
   每次构建在自己新起的 JVM 里跑，坏令牌无法跨构建传染（代价 ~20 s）。
   `gen/android/gradlew.bat` 是 shim，最终调真 `gradle.bat`，后者会把 `%GRADLE_OPTS%` 传给 JVM。

🕳️ 排查时走过两条弯路，记下来省下次：**(a)** 以为是"沙箱拦 hardlink"（有 `sandbox bypassed`
提示）—— 实测沙箱内、沙箱外**都**失败，与沙箱无关；**(b)** 以为是 ACL/磁盘/文件锁 ——
`icacls` 看得到权限正常、`sudo taskkill` 杀掉那个守护进程后**当轮构建立刻通过**，
这才是决定性的对照。

### ② `setup-gen-android.sh` 改模板不生效：判据是"有没有补丁标记"

原逻辑是「五个标记都在 ⇒ 跳过写 `MainActivity.kt`」⇒ **改了模板重跑脚本也不生效**，
生成物永远停在首次写入那一版，而自检还照样报"横屏沉浸补丁: 8"（它只数标记个数）。
⇒ 已改成**按模板版本号判**：模板头里写 `HS-GEN-REV: <版本>`，脚本里 `_GEN_REV='<版本>'`，
不一致就整文件重写。**改模板必须同时把两处 +1**（本轮就靠它才发现又一次没生效）。

### ③ cargo 缓存里的 **0 字节文件**：报错长这样

磁盘写满会留下截断的缓存文件 ⇒ 链接期报

```
windows.0.52.0.lib : fatal error LNK1136: invalid or corrupt file
```

完全指向别处。清点与修复见 `scripts/fix-cargo-zero-byte.py`（**默认只报告**，`--apply` 才写）。
🕳️ `.crate` 是 **gzip 过的 tar**：用 Python `zipfile` 打开会报 "not a zip file"，
必须 `tarfile.open(fileobj=gzip.open(...), mode="r:")`。缺归档的那几个只能联网重下。


### ⑥ 系统级手势（边缘返回等）**没法**用 adb 注入来验证

`adb shell input swipe x0 y x1 y 160` 与 `input motionevent DOWN/MOVE/UP` 注入的边缘滑动
**都不会触发系统的边缘返回手势**（实测真机 Android 15 + 手势导航：
连**未被排除**的那一段也不退出 ⇒ 命令本身就不触发，不是我们的 exclusion 生效了）。

⇒ 纪律：**凡是"系统手势相关的行为"判据，必须先跑一条对照（预期会触发的那一段）**；
对照不成立就**如实标"不可判"**，别把它算成通过。取硬证据改用**应用自己打的一行 logcat**
（例如 `HS-EDGE exclusion rects=…`）。

### ⑦ `wm density` ≠ 应用的 `resources.displayMetrics.density`

实测真机：`wm density` = 560dpi（3.5），而应用里 `density` = **3.0**。
凡是按 dp 换算像素的判据（如"排除带 200dp"），用 `wm density` 算会差 100px，
**把做对了的实现判成失败**。⇒ 期望值从**应用自己的读数**里推（或从它打出的日志里解析）。

### ⑧ 真机 `dumpsys activity activities` 单行可达**上万字符**

ColorOS 的 `mGlobalConfig={…}` 一行就上万字符。按"从包名往后切 N 字符再取字段"的写法
在真机上**切不到**（`resizeMode` 就是这样读成 `null`、把"已屏蔽分屏"报成失败）。
⇒ 改成**逐条匹配字段、再往前看几万字符里有没有本包名**，别按位置切窗口。

### ⑨ 「面板开关」事件是**开/关分开**的，别拿一个当另一个用

`hs-mobile-switch-tab`（`{tab}`，**累加语义，只能开**）与 `hs-mobile-close-panel`（`{key}`，关）。
用前者传 `open:false` 是**空操作** ⇒ 面板一直开着 ⇒ 量到的 CSS 动画 `playState` 全是 `finished`
（上一轮播完留下的），**判据看着通过其实什么都没测**。判"动画有没有播"要看
`el.getAnimations()` 的 `playState` + 一串 `opacity` 采样，**别看 `animationName !== 'none'`**（规则命中≠在播）。


### ⑩ 「手柄在块内部」时，比例一律按**位移增量**算，别按指针绝对位置

分屏的拖动手柄往往不是分界线本身，而是"**下面那一块自己的标题条**"（本项目的
参数工具栏 / 文件标题栏 / 记事本标题栏都如此），它可能在块内部、离分界几十像素。
用 `t = (clientY − 上块.top) / 两块的span` 会让**一起手就偏**：实测把 18% 的拖动量
算成 0.98 ⇒ 越过"拖到底自动关闭"的阈值 ⇒ 面板被关掉，判据看起来像"拖动没生效"。

⇒ 一律 `t = 起始比例 + (clientY − startY) / span`（位移增量口径）。

### ⑪ 拖动量要按"被调那一对的高度"给，别写死像素

同一段手势，在"两块各 75px"和"两块各 400px"下写死 `+60` 的含义完全不同：
前者等于跨过塌陷阈值。⇒ 判据里用 `span * 比例`，并避开阈值区（0.14 / 0.86）。

### ⑫ 持久化的布局参数会让"下一次探针"从脏状态开始

分屏比例/权重是写 localStorage 的 ⇒ 上一轮探针跑完可能留下 172px vs 23px 这种极偏状态，
下一轮判据"一起手就跨阈值"⇒ 误判。⇒ 判据**先归中**再测（归中的动作本身也是在用功能）。


### ⑬ 同一个「收窄」写两个元素时，先确认它们在**哪个弹性轴**上

CSS 的 `flex` 简写同时定 grow/shrink/basis，而 **basis 管哪个轴取决于父的 `flex-direction`**。
本项目 `index.css` 的"收起轨道头"规则把**内层列表**（父是 column ⇒ basis 管高度）与
**外壳列**（父是 row ⇒ basis 管宽度）写在一起，共用 `flex: 0 0 auto`：

- 内层本来的 `flex-1`（`1 1 0%`）被 `grow: 0` 抹掉 ⇒ **高度塌成内容高**（实测 284 → 112px），
  左侧轨道头只显示 1 行多、与右侧轨道区**纵向错位**。
- 正确写法：内层**一个字都不写 flex**（保留 `flex-1`），只有外壳写 `flex: 0 0 auto`；
  宽度统一交给 `width/min-width/max-width`。⚠️ 两者互换会让外壳与时间线**平分宽度**。

⇒ 纪律：写"收窄某元素"的规则时，**先问它在父里是主轴还是交叉轴**；能不用 flex 就不用。

### ⑭ 事件桥的语义要先读实现：`toggle` 不能当"关闭"用

`hs-mobile-close-panel` 内部是 `dispatch(toggleMobilePanel(key))` —— **toggle**。
探针想"关掉某面板"时若它本来是关的，会被**打开**（本轮因此把 `params` 挤掉、
一条判据整条不可判）。`hs-mobile-switch-tab` 则是 `showMobilePanel`（累加开、幂等）。
⇒ 纪律：动面板显隐前先读 `[data-hs-pane]` 现状，**只对真在场的**发 toggle。
