## 视口内核 / 手势层（规范 docs/08，工具 docs/13）

- `renderKernel/scrollKernel.ts` = 视口真值唯一来源；scrollLeft 与 pxPerSec **必须同帧送达**。
- `touchGesture.ts` `TwoFingerGestureController`：死区 16px、单轴锁定 <24px、三指纯平移、
  2→1 指 150ms 冷却；**每表面轴向策略** `attachSurface(el,"x"|"y"|"both")`，会话起手按
  "两指落在哪个表面"定轴（`axisForSession`）；**被禁的轴既不缩放也不平移、也不提交 viewport**。
- ⚠️ **挂表面必须一起决定 `touch-action`**：不滚动的（拍数栏）`none`；**自己滚的**（轨道列）不能禁，
  用 `suppressTwoFingerScroll(el)` 只在 `touches.length>=2` 时 `preventDefault`。
  `pan-y` 不行（双指竖向捏合被当滚动 ⇒ `pointercancel`）。
- **单指绝不 `setPointerCapture`**：捕获态让 WebView 不合成原生 long-press → contextmenu
  （上游 45 处右键菜单全靠它）。第二指落下才 capture。多表面**必须喂同一个 controller**；
  状态机要能**自愈**；拍数栏挂**整行根节点**（tempo-map 标签等是兄弟）。
- 🕳️ 拍数栏 seek：标尺 `onMouseDown` 里 `isLegacyMouseEventFromStylus()` **对 touch 也返回 true**
  ⇒ 手机上没反应。已加 pointer 专用路径 `bindRulerTouchSeek`。
- 🕳️ **值域轴反向**（`valueToY` 里 `y=(1-t)*H`）：行↔值域必须 `scrollTop = -center*rowHeight`。
- 🕳️ 参数编辑器纵向缩放"像没生效"：`syncVerticalScrollbarForViewport` 只写内核镜像、**没回写 ref**，
  而双指 `setVertical` 直接调它 ⇒ 下一手势基准陈旧、缩放被拽回。已回写。
- 🕳️ **纯平移会被 React 丢掉**：缩放入口只写 `horizontalZoomPendingRef`，落地的 `useLayoutEffect`
  依赖里**必须带 `scrollLeft`**（否则 `setPxPerSec(同值)` 被 bail out）。
- 触屏拖拽（滚动条 thumb / range / 旋钮）一律 `touch-action: none`。
- ⚠️ 水平捏合残留 **~3.66px 锚点漂移**（`漂移 = C·(k−1)`，C≈3.9px 是内核 screen↔sec 常数偏移）。
  **已决定不修**（≈0.9ms 不可见），见 `docs/03 §7.7`。

## 实测卡点（全文 docs/10）

1. **`ndk_context` 从未被 Tauri 栈初始化**，cpal 的 Oboe 后端强依赖它 ⇒ 必 panic。解法（零 Kotlin）：
   `JNI_OnLoad` 拿 JavaVM → `ActivityThread.currentApplication()` 取 Context → 全局引用 → 初始化。
2. **onnxruntime**：`.so` 进 `jniLibs/<abi>/`、`load-dynamic` + 裸 soname；**绝不直接引用
   `ort::sys::Ort*`**（⇒ `dlopen` 期 `UnsatisfiedLinkError`），走 `ort::api()`。
3. **路径**：`resource_dir()` = `asset://localhost/`；`app_data_dir()` = `/data/user/0/<pkg>`。
4. **SAF v1**：`pick_file`/`pick_files` 真弹窗；`pick_folder`/`save_file` 返 `None`（v2）。
   `dialog.rs` → `saf.rs`（JNI 回调 + mpsc）→ `HifishifterFs.kt`（**边界物化**到 `cacheDir/saf_import/`）。
   🕳️ 不能用 `env.find_class()` 找 app 的类（native 附加线程只有系统类加载器视野）。
5. **模型导入**：只收 `.onnx`、小文件随包 ⇒ 落点与 `resources.rs` 同树 ⇒ 加载侧一行未改；
   `校验 → .part 原子落位 → 免重启激活` 已实测。
6. **推理 RTF ≈ 0.48** ⇒ 可边播边合成；**块长上限 1024 帧**。
7. **减包（ADR-012）**：**270.8 → 165.1 MB**。🕳️ **改完 conf，APK 一个字节都不会小**
   （tauri 拷资源进 `assets/` 却**从不清理**已删条目；`build-apk.sh §⑤.5` 清期望集外目录）。
   🕳️ 🔴 **`bool::then_some(x)` 会先无条件构造 `x`** ⇒ `AAsset_close(NULL)` → **SIGSEGV**
   （资源随包就**永远测不到**）。🕳️ 减包后必测 **`pm clear` 后全新安装**。
8. **真机喂测试音频**（绕开 SAF）：app 读不了 `/sdcard/` ⇒ **PC 做桥**：`exec-out cat` → PC →
   `push /data/local/tmp` → `run-as cp` 进 `files/media/`；再 CDP 调
   `import_audio_item({audioPath, trackId:null, startSec:null, mediaAudioStreamIndex:null})`。
   ⚠️ `trackId` 传 **`null`** 而非 `undefined`。
9. **参数编辑器两种模式**：**轨道**（音高/共振峰/气声/张力/音量/声像/算法）与
   **音符**（颤音：波长/振幅）。⚠️ `set_param_editor_mode` **不是后端命令**（纯前端状态）⇒ CDP 切不了。
10. **后端片段语义**：全子树选择 ⇒ 粘贴产出 **Tracks fragment**（不是"只多一个块"），
    有单测（`project_fragment.rs`）⇒ 想改属**语义变更，先问用户**。

## CDP 验收（唯一能脚本化验多指的路子，全文 docs/13）

```bash
PID=$(adb -s <serial> shell pidof com.arounder.hifishifter | tr -d '\r')
adb -s <serial> forward --remove-all      # 多设备时必做，否则端口被占
adb -s <serial> forward tcp:9222 localabstract:webview_devtools_remote_$PID
```

- wry 在 **debug 构建**自动开 WebView 调试 ⇒ 零改动。⚠️ 设备须**亮屏 + 应用前台**，
  否则 `visible:false`（`svc power stayon true` + `input keyevent 224`）；🕳️ **真机尤甚**：
  不亮屏量到 `innerWidth=0`。后端日志读 `run-as … cat logs/android.log`（**logcat 抓不到**）。
- 🕳️ **CDP 求值的函数不是闭包**：A 调 B ⇒ B `not defined`。每个函数必须自包含。
- 🕳️ 求值不稳 ⇒ **重建 `forward`** 再试；带 `sleep` 的复杂脚本易超时返回空。
- 🕳️ **DOM `dispatchEvent` 只能验「视觉/布局/属性」，验不了「React 事件是否接上」**：
  `onClick` 比 `onPointer*` 靠后，需完整 pointerdown→pointerup→click 且由真实输入产生
  ⇒ 交互类（点开菜单）**必须 CDP `Input.dispatchTouchEvent` 或真机手测**。
- CDP `Input` 域**没有 `enable`**；双指序列 `touchStart[p1]` → `touchStart[p1,p2]` →
  `touchMove`×n → `touchEnd[]`。坐标是 **CSS px、相对 WebView 视口**。
- 钩子：`__hsViewport()`、`__hsParamViewport()`、`__hsGestureActive`、`__hsOverlaysVisible`、
  **`__hsGestureDebug`**。🕳️ 其中 `rowH` 走 `viewport.get()`，参数面板那条经值域 ref、
  陈旧时**撒谎** ⇒ 用 `ky × rowH0` 反算。
- **直接调任意命令**：`window.__TAURI_INTERNALS__.invoke('<cmd>', {arg})`。第二参数是**对象**、
  键名 `camelCase`（传错报 `missing required key xxx`，正好反查键名）；返回 Promise
  ⇒ 「写 `window.__r=…` + 隔几秒回读」。
- **导航 SAF 选择器**：抽屉(`tap 88 208`) → 目录 → 点**文件卡片中心**。🕳️ 抽屉条目顺序随 MIME 过滤变化。
- 🕳️ **长按菜单要靠真实 `contextmenu`**：CDP `dispatchTouchEvent` 不经过那层识别
  ⇒ `tap --hold` 永远打不开。用 `scripts/_probe-trackctx.mjs`。
- 🕳️ **模拟器的系统剪贴板是空操作** ⇒ 剪贴板类功能只能上真机验。

### 探针方法论（2026-09-27 新批次踩出）

1. **两种触摸驱动不能混用**：React `onPointer*` 用**合成 `PointerEvent`** 最稳
   （CDP 触摸落点/时序不稳：长按菜单打不开、捏合 `kx` 读到上一次会话残留）；
   `TrackList` 的**原生 touch** 监听（排序/左划收起）必须用**真实 `TouchEvent`**。
2. 判"是否可见"用 **`innerText`**（`textContent` 含 `display:none` 的内容）。
3. 点空白避开容器最底 ~**14px**（横向滚动条预留带，点它会滚到末尾）；
   长按/角标类监听挂**内层 span**（事件只冒泡不下降）。
4. 拖拽别靠近容器边缘 **32px**（`DRAG_EDGE_SCROLL_BAND_PX` 会自动滚屏、放大位移）。
5. 探针**互相独立**（开头先"停止播放"）。
6. 块的行坐标取 `[data-hs-track-row]`，别按"扁平下标 × rowHeight"算。

## 🎯 C 盘动不动就满：总根因是 `C:\pagefile.sys`（2026-09-27 查实）

**症状族**（看起来互不相关，其实同一个根因）：

| 表现 | 真因 |
| :--- | :--- |
| Gradle 失败，任务名却跟磁盘无关，日志一句 **GBK 乱码** `´ÅÅÌ¿Õ¼ä²»×ã¡£` | 磁盘满 |
| `build-apk.sh` 一启动就死：**`cygheap read copy failed … Win32 error 299`**，`dirname` 崩溃 ⇒ `$ROOT` 空 ⇒ `//scripts/android-env.sh: No such file` | **MSYS 满盘下的 fork 故障**，脚本没坏 |
| `cargo metadata` → **`os error 193`（%1 不是有效的 Win32 应用程序）** | `~/.cargo/bin/rustup.exe` 被**截成 0 字节**（而 `cargo.exe`/`rustc.exe`/`rustdoc.exe` **全是指向它的符号链接** ⇒ 一个坏、全线坏） |
| `git --version` **输出 0 字节、退出码 0**，所有依赖 git 的脚本报"全都错" | PortableGit 被截成 0 字节 |

**机制**：内存压力（**模拟器在跑** + Gradle / tsc / cargo 并发）会让**系统托管的页面文件**在 C 盘疯涨。
实测：`pagefile.sys` **42.6 GB**；`adb emu kill` 后 **20 秒内 27.6 GB，C 盘 204 M → 16 G**。
把模拟器开回来做探针后又涨回 **28.2 GB、C 盘只剩 1.1 G** —— **这条极顽固**。

### 行动规则

1. **铁律：构建 / 任何重活之前先关模拟器。** 构建根本不需要它，只有**装机 / 探针**才要。
2. **判据**：`df /c` 掉的量**远大于**你正在做的事 ⇒ 直接 `ls -la /c/pagefile.sys`，别去翻别的地方。
   实测"用户目录里没有大头"：最近 75 分钟的大文件合计才 0.41 GB（还都是 Edge 缓存 / 游戏 dump）。
3. **根治（需用户 / 管理员）**：把页面文件挪到 D 盘并**设固定大小**；`powercfg -h off` 再省 `hiberfil.sys`（本机 6.7 GB）。
4. 腾空间只用 `truncate`，**但回收站不释放空间**：`Remove-Item` 与 **`robocopy /MOVE` 都进回收站**
   （实测源目录消失而 `df /c` 一个大字节都不变）⇒ **AI 只能做到复制 + 校验，最后清空必须用户跑**。

### 🕳️ 界定"被打成 0 字节"的范围：用 mtime，不要用计数

Windows 上 0 字节文件**大量是正常的**：`~/.gradle` **3956 个**、`D:\gradle-home` **1542 个** 全是正常空 lock。
直接数会把自己吓死。**按事故时刻筛**：

```bash
find <目录> -size 0 -type f -printf '%TY-%Tm-%Td %TH:%TM\n' | sort | uniq -c | sort -rn
```

同一分钟出现成百上千个 = 事故；时间戳散在各年月的 = 正常。
（实测 `.cargo`/`.rustup`：`20:xx` **219 个** = 事故，`1970`/`2006` 等 374 个 = 正常。）
